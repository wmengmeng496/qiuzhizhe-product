# 职引简历专家

面向中文求职场景的 WorkBuddy 简历优化专家。专家根据用户提供的真实简历和目标岗位 JD，分析岗位要求、优化求职表达，并将优化版本保存到职引简历工作台。

## 核心能力

- 分析目标岗位的硬性条件、核心能力和 ATS 关键词。
- 优化个人总结、工作经历、项目经历、技能描述和自我介绍。
- 保持事实边界，不虚构公司、项目、职责、结果、数字、技能或教育经历。
- 查看当前账号套餐、可用额度和最近的简历优化记录。
- 将优化结果同步到职引简历账号，便于后续查看和继续修改。

## 使用流程

1. 在 WorkBuddy 召唤“职引简历专家”。
2. 按连接引导打开浏览器，登录或注册职引简历账号。
3. 核对授权范围并同意绑定。
4. 提供简历正文和目标岗位 JD，岗位名称和公司名称可选。
5. 确认允许将本次材料发送到职引简历进行 AI 处理。
6. 专家调用工具完成优化，返回岗位判断、优化正文、关键词、修改说明和待补充信息。

推荐提问：

- “根据这个前端开发岗位的 JD 优化我的项目经历。”
- “查看我最近 5 次简历优化记录。”
- “查看我的套餐和剩余额度。”

## 账号连接与权限

MCP 地址：`https://www.qiuzhijianli.xyz/api/mcp`

连接采用 OAuth 2.0 Authorization Code + PKCE S256。密码只在职引简历网站输入，不会交给 WorkBuddy 或专家。用户可在职引简历个人中心随时撤销连接。

| 权限 | 用途 |
| --- | --- |
| `openid` | 确认当前登录账号 |
| `profile` | 读取昵称、套餐和额度摘要 |
| `resume.read` | 读取最近的简历优化记录摘要 |
| `resume.write` | 执行简历优化并保存结果，会消耗账号额度 |

## MCP 工具

### `optimize_resume`

根据目标岗位优化并保存简历。调用前必须取得用户对本次 AI 处理的明确同意，并同时具备有效简历正文和目标岗位 JD。

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `resumeContent` | 是 | 用户真实简历正文，至少 20 个字符 |
| `jobRequirements` | 是 | 目标岗位 JD，至少 20 个字符 |
| `jobTitle` | 否 | 目标岗位名称 |
| `company` | 否 | 目标公司名称 |
| `optimizeMode` | 否 | `full`、`project`、`intro`、`experience` 或 `skills` |
| `model` | 否 | 用户套餐允许使用的模型，通常不需要主动指定 |

### `list_resume_optimizations`

读取当前账号最近的优化记录摘要。可选参数 `limit`，范围为 1-20，默认 10。该工具不会创建新版本或消耗优化额度。

### `get_account_summary`

读取当前账号的昵称、套餐、额度和工作台地址。该工具无参数，不会消耗优化额度。

## 输出要求

一次完整优化应包含：

1. 岗位匹配判断和主要差距。
2. 可直接继续修改的优化后正文。
3. 已覆盖和仍缺失的关键词。
4. 主要修改及修改理由。
5. 需要用户补充或确认的事实。
6. 保存状态、匹配分和额度变化，以工具实际返回为准。

不得把建议写成已经发生的事实。缺少业绩数字时，应询问用户或标注“待补充”，不得自行生成数字。

## 常见问题

- **授权失效或未连接**：重新完成职引简历账号授权后再调用工具。
- **权限不足**：检查是否授权了对应 scope；只读授权不能调用 `optimize_resume`。
- **材料不足**：补充完整简历正文和目标岗位 JD 后再优化。
- **额度不足或模型不可用**：调用 `get_account_summary` 核对套餐和额度，告知用户可用选项，不要反复重试。
- **服务暂时异常**：保留用户原文，说明失败阶段，建议稍后重试；不得声称结果已保存。

## 隐私与安全

- 仅在完成用户明确请求所必需的范围内处理简历内容。
- 不在回复中暴露 access token、refresh token、授权码或其他凭据。
- 未成功调用并收到保存结果前，不得声称已经保存。
- 用户只查询历史或额度时，不调用写入工具。
